**Crypto-G 审计整改与交易目标优化方案 V1.0**

日期：2026-10-18。状态：优化方案，尚未实施。

依据：[2026-10-18全面审计报告](D:/Crypto-Google/audit/项目全面审计与交易适配评估-2026-10-18.md)、当前AGENTS.md及short-horizon-v2开发方案。审计现场数据属于当时快照，实施前需重新核对运行状态与磁盘容量。

目标：服务于币安BTCUSDT现货做多、通常5分钟–6小时的短线交易，围绕整笔扣费后收益≥0.8%的目标，建立准确、可复核的预警和执行记录体系。风险退出可以早于5分钟。收益与胜率是否可达由验证决定。

**总体路线：先修复可信度，再补齐执行记录，最后验证交易目标。**

现有前后端架构继续使用，不必重写APP。第一批交付解决错误数据、费用偏低、信号丢失、结算错误与磁盘增长；第二批建立数据、推送和成交的完整记录；第三批用同一执行逻辑重做研究与晋级。完成软件整改不等于策略取得交易级资格。

本方案不修改S1–S5既定数值。BTC现货、只做多、成本下限、结构止损、最大1.20%止损距离、0.5%单笔风险建议、最长6小时、90分钟时间止损、熔断及AI权限均保持。观察级继续按既定规则推送；熔断暂停交易级推送。S5保持研究用途，AI不生成价格、不发起BUY。任何后来涉及策略数值的改变，应另立规则变更与验证记录。

**一、把0.8%的目标定义清楚**

默认定义：一笔交易全部退出后，相对该笔实际投入本金的净收益至少0.8%，而不是账户总资产收益、瞬间浮盈、TP1触碰或某一半仓位收益。

| 指标 | 定义 | APP呈现 |
| --- | --- | --- |
| 整笔实际净收益 | 卖出现金流−买入现金流−实际费用，按投入本金归一化 | 已平仓才给最终值；未平仓展示已实现与未实现两部分 |
| 模拟净收益 | 模拟成交路径扣对应版本成本后的结果 | 明示“模拟”，与真实成交分列 |
| 净胜率 | 完整结算交易中净收益>0的比例 | 同时显示笔数、统计区间、规则版本 |
| 0.8%达成率 | 完整结算交易中整笔净收益≥0.8%的比例 | 分母包含亏损、时间退出及保本交易，不仅统计盈利交易 |
| 净期望 | 全部完整交易净收益的平均值 | 与盈利因子、回撤和连亏一起展示 |
| 账户收益 | 真实资金占用及所有成交形成的账户变化 | 与单笔仓位收益分开；固定500 USDT孪生不能代替账户曲线 |
| 计划空间 | 结构目标在最差入场价下的收益情景 | 是条件计算，不显示为保证收益或预测胜率 |

依照项目0.24%的模拟成本，单价全仓退出净赚0.8%约需1.04%的毛涨幅。分批退出时：整笔净收益≈各段净收益按初始仓位权重加总。例如一半净+0.8%、一半净保本，整笔约+0.4%；一半净+0.6%、另一半净+1.0%，整笔约+0.8%。实际成交以逐笔现金流计算，避免简化公式覆盖手续费扣币、部分成交等情况。

暂不人为指定“0.8%达成率必须达到多少”。先在统一口径下取得样本；样本外净胜率、期望、回撤与达成率共同决定是否符合目标。提高TP价位或改变分批比例不是本批整改内容。

**二、交付分为五个阶段**

| 阶段 | 内容 | 对应审计 | 完成标志 |
| --- | --- | --- | --- |
| A 运行与信号修复 | 磁盘治理、闭合K线、周期门槛、评分协议、发送前报价复核 | F01/F02/F04/F06/F07 | 复现缺陷转为回归测试，线上可重放输入正确 |
| B 成本与结算统一 | 成本快照、分批退出、入场分钟、时间边界、旧数据版本隔离 | F03/F05 | 同一交易前端、后端、回放计算一致 |
| C 数据与执行闭环 | 多周期K线、候选漏斗、AI配置、成交与设备送达记录 | F08/F09/F11 | 能解释每个候选为何未发、未成交或退出 |
| D 独立验证与晋级 | 重算基线、样本划分、PBO/DSR、14天影子与14天试运行 | F10/F11 | 合格模块单独晋级；证据不足保持观察级 |
| E APP验收与发布 | 净收益页面、账户风险提示、版本与签名、真机测试 | 前端专项 | 可安装、可回滚，用户能看懂并核对每个数字 |

A阶段的磁盘治理最先安排；A/B完成后才能生成新的正式研究标签。C可在数据契约稳定后推进。E的页面工作可随B/C开展，正式交付依赖对应接口和真机验收。D的研究准备可以提前，但盈利验收必须使用修正后的代码和数据。

不以固定开发天数承诺交易级上线。完成工程整改后，仍有数据补齐、样本积累以及至少14天影子、14天试运行的时间要求；天数到期但证据不足就延长观察。

**四、B阶段：统一费用、成交和退出**

统一成本不等于对每个数字机械减0.24%。分别处理计划、模拟、真实成交，防止把已体现在成交价里的滑点再次扣除。

| 场景 | 成本与价格处理 |
| --- | --- |
| 信号筛选与建议仓位 | 工作成本=max(当前适用成本下限，按当时可见真实成交估算的成本)；默认无BNB抵扣下限0.24% |
| 影子/模拟成交 | 买入使用卖一、卖出使用买一或明确的执行模型；完整记录价差与滑点是否已在价格中计入，剩余成本不重复扣 |
| 真实成交盈亏 | 用实际成交价、数量、手续费和手续费资产折算；不再额外扣一遍预设滑点/价差 |
| BNB抵扣 | 只有显式设置并可核对时采用0.19%下限；本次不改变用户现有抵扣偏好 |
| 旧记录 | 原始记录只读保留；旧0.11%记录标明旧口径；修正重放另存结果并关联原记录 |

每个计划及仓位保存costModelVersion、成本来源、适用时间、手续费/滑点/价差计入方式。历史回测只使用当时已经可见的校准样本；禁止把未来成交测得的低成本应用到过去。开仓后账本保留原计划快照，若执行成本重新估计，需要单独记录变更，不能悄悄改写原始收益预期。

| 任务 | 实施方案 | 验收案例 |
| --- | --- | --- |
| B01 贯通成本 | 引擎门槛、入场复核、仓位、保本线、模拟和统计读取同一成本契约 | 测得成本0.60%时，筛选和风险计算采用0.60%，不继续使用0.24%；不得低于下限 |
| B02 整笔收益 | TP1、余仓、最终成交分别记账；按成交数量和实际费用汇总；模拟提供整笔净收益情景 | 半仓净0.8%+半仓净0%=整笔约0.4%；多次卖出后数量与费用守恒 |
| B03 入场分钟 | 精确记录filledAt；只允许成交后路径影响退出；只有整根分钟OHLC且无法恢复顺序时标记PATH_UNCERTAIN | 90秒入场不能被已知发生于70秒的低点判止损；不能通过简单跳过整根入场K线制造好结果 |

| B05 90分钟与实时提示 | 明确90分钟检查的事件时间，与影子和实际仓位提示一致；提示、用户确认、实际成交分开记录 | 已提醒不当成已卖出；通知重试不重复记部分退出；断网恢复后记录延迟而非伪造及时成交 |

**五、C阶段：把每次机会和执行结果记录完整**

采用两层记录：原始形态/拒绝原因进入候选诊断；通过原有硬门槛并满足成交条件的计划进入策略影子仓。被AI否决的有效计划仍开影子仓。因成本、结构或数据不足而没有有效交易计划的形态，可以研究，但不能混成策略的正式成交样本。

记录顺序为：形态出现→环境/风险筛选→等待入场区间→可成交候选→AI意见→推送请求→FCM接受→手机收到/打开→实际或模拟成交→分批退出→完整结算。每一步保存时间、版本和失败原因；FCM接受不等于手机已收到。

| 任务 | 实施方案 | 验收标准 |
| --- | --- | --- |
| C01 K线积累 | 持久保存BTC的1m/5m/15m/1h/4h/1d闭合K线；以市场+周期+开盘时间幂等写入；启动回补缺口 | 重启无重复；断流补齐；线上可查询实际覆盖和缺口，不能仅检查表是否存在 |
| C02 指标输入一致 | 实盘与回放共用指标种子、窗口长度、时钟、环境门槛及执行版本；把既有计算口径显式配置并锁定 | 相同输入得到相同特征、门槛结果及交易计划；任何窗口调整都列为可审查差异 |
| C03 候选漏斗 | 统计无形态、环境关闭、止损过宽、净收益不足、RR不足、未回踩、逃逸作废、过期、AI否决、推送失败 | 每个未成交候选可追溯主原因；不同漏斗层的数量不互相冒充 |
| C04 AI接线 | 复用服务端凭据读取与开关；v2审查读取引擎A输出；8秒超时/格式异常PASS并记录回退原因 | 真实配置通路能调用；关闭、缺key、超时、坏格式可区分；不能通过AI输出修改价格 |
| C05 AI价值核对 | 每次意见关联候选与影子结果；否决达到100笔后按既有规则评估；报告分环境结果和样本差异 | 无法改善的否决不继续保留权限；样本不足显示未验证，不能宣称已提高胜率 |
| C06 成交核对 | 优先补齐手工/文件导入的成交、费用、数量与时间；为未来只读币安接口预留适配器 | 一笔多次成交、部分卖出、费用扣BTC/BNB、重复导入均可核对；对账差异不静默修正 |
| C07 账户风险提示 | 余额与持仓有来源/更新时间；展示全部已知BTC多单的合计计划风险；余额缺失或陈旧时不显示精确风险金额 | 0.5%单笔风险建议与实际数量相符；未知持仓明确显示覆盖不完整；不另设未经验证的风险数值 |
| C08 数据身份隔离 | 成交待同步队列绑定服务器/账户身份；退出设备绑定保留原有隔离；迁移旧队列须明确归属 | 换服务器不把原服务器的待同步成交发到新服务器 |

真实成交导入与只读API是两种接入方式，前者可先交付。创建币安密钥、接入个人账户或自动下单不属于本次方案生成动作；未来实现应另明确接入范围。手机通知功能保持监控辅助定位。

**六、D阶段：重做验证，再决定是否值得交易**

目前S2旧报告样本外34笔净胜率17.6%，其他交易模块无样本外成交。先重算修复后的规则，不依据旧结果直接选“最优模块”。S1保留原方案的优先研究顺序；S2重点分析过滤原因与亏损结构；S3/S4先纠正环境门槛；S5继续只研究。

验证分两条轨道：一条复现修正后的short-horizon-v2既定规则；另一条统计同样交易中整笔≥0.8%的达成率及限制因素。不得通过延长持仓、抬高结构目标或缩紧止损来人为满足0.8%。

| 环节 | 实施要求 |
| --- | --- |
| 版本冻结 | 固定代码哈希、规则参数、数据范围、执行模型、成本模型、测试清单和试验编号 |
| 历史重放 | 按时间顺序只读当时可见数据；共用生产判定；至少1分钟执行路径，有可靠tick/盘口时采用更细粒度 |
| 成交现实性 | 模拟提示后才可执行，纳入实测推送/人工操作延迟；限价触碰不一概等于成交；未成交单单独报告 |
| 持仓约束 | 同一形态去重、持仓重叠、资金占用与账户模拟一致；单模块统计和组合资金曲线均报告 |
| 样本隔离 | 已用于选规则、看过结果的旧样本外区间只能作诊断；新结论使用事先封存的独立区间或未来数据 |
| 清洗前推 | 训练标签不得跨入验证区间；使用既定6小时禁区；周期、市场环境及事件分组避免重叠泄漏 |
| 置信区间 | 保留既定bootstrap下限门槛；针对重叠/成簇交易增加按日或事件分块的敏感性评估，不能只用独立样本假设 |
| 试验登记 | 记录所有实际尝试的配置及失败结果；不能只保存最后赢家并将nTrials重置为1 |
| PBO | 用实际试验在同一时间轴上的收益矩阵评估；样本/试验不足显示无法计算并禁止晋级，不编造配置补数 |
| DSR | 试参超过20组时必须>0.95；估计方法、选择偏差校正及输入证据可复核 |
| 成本压力 | 主报告按既定工作成本；另报告更高成本及更长延迟下的敏感性，不能用压力结果倒调硬参数 |
| 否决验证 | 保留被否决信号的影子结算；与通过样本按时间/环境分组比较，不能只看少量均值 |

若只有一套可比规则而PBO无从估计，保持研究状态并如实说明。不能以“只有一套参数”为由把必需PBO门槛自动视为通过；若今后需要替代验证方案，另行变更验证规范。

| DSR | 实际试参>20组时>0.95 |
| 交易级频率 | 0.5–6条/天，不能靠重复候选凑数 |
| 波段召回 | ≥1.5%波段中，至少50%在前1/3有候选；另列可成交候选召回，S5不冒充交易候选 |
| 发布阶段 | 合格后14天影子，再14天试运行；阶段结束再次核对样本、数据质量及既有回滚条件 |
| 自动回滚 | 保留最近30笔净期望<0或回撤>6R的规则 |

影子阶段的记录数以唯一候选/独立交易计，不按每秒扫描累加。观察级按当前项目规则继续推送并标明未验证；正式交易级受熔断约束。阶段到期但缺少有效记录或关键统计不可判定时，不自动晋级。若全部模块未通过，交付“未通过原因与继续采样计划”，不能用功能开发完成代替盈利验收。

**八、发布、迁移与回滚**

1. 实施前保存当前源码清单、数据库一致性备份、配置结构和脱敏统计；先核对空间，不在空间不足的系统盘盲目再复制一份巨型备份。
2. 新增字段/表采用向后兼容迁移。每笔记录注明APP、引擎、规则、成本及执行模型版本；旧标签保留，修正标签另存。
3. 先验证修正引擎的离线重放，再做并行观察对比；对照环境不重复发真实手机通知。确认数据和退出链路后再切换。
4. 生产切换后检查实际closed-bar时间、信号解析、研究写入、磁盘增量、未平仓数量和推送队列；不能只看systemd为active。
5. 出现迁移异常、数据污染、规则违例或退出链路故障时，停止新交易级准入并恢复兼容版本；保留当前持仓监控和审计证据。故障回滚不能直接覆盖上线后新增成交记录。
6. APP实际发布时遵守项目规则：versionName+0.01、versionCode+1；输出D:\Crypto-Google\release\Crypto-G V{versionName}.apk。发布前重读当前版本，不提前占用版本号。Debug/Release使用独立暂存目录，最终交付只复制经过验证的目标包，附构建类型、签名标识及SHA256，防止同名覆盖。
